# Онлайн-комнаты и Telegram Mini App — дизайн

Дата: 2026-09-23
Статус: согласован с заказчиком (VPS + Docker)
Основа: `2026-09-22-card-game-design.md` (правила, §3.2–3.3 сервер и протокол), `2026-09-22-web-local-design.md` (клиент; шов `GameClient`).

## 1. Цель и рамки

Игрок открывает бота в Telegram, нажимает «Играть», видит своё имя и фото, создаёт комнату, отправляет друзьям ссылку — друзья попадают прямо в лобби. Партии идут на сервере; правила — тот же движок `@vakhta/engine`.

**Входит:** сервер комнат (Node + WebSocket), вход через Telegram, бот с кнопкой Mini App, лобби с кодом и «Пригласить», ссылка-приглашение, переподключение, заполнение пустых мест ботами, сессия дня и итоги на сервере, Docker-деплой с HTTPS (Caddy).

**Не входит:** аккаунты вне Telegram, база данных (комнаты в памяти; интерфейс `RoomStore` остаётся), чат/эмодзи, рейтинги, публичный поиск соперников. Локальная игра с ботами в браузере сохраняется как режим «Тренировка».

## 2. Сценарий

1. `/start` → бот отвечает текстом и кнопкой **«Играть»** (`web_app`). У бота настроена и кнопка меню на тот же URL.
2. Mini App открывается с `initData`. Клиент шлёт её серверу при подключении; сервер проверяет подпись HMAC токеном бота (срок `auth_date` ≤ 24 ч) и создаёт/находит игрока: `id = tg:<user.id>`, имя = `first_name [last_name]`, аватар = `photo_url` (если нет — эмодзи-заглушка по id).
3. Главная: аватар и имя; **«Создать игру»**, **«Войти по коду»**, «Тренировка с ботами».
4. «Создать игру» → настройки (как сейчас: игроки, колода, время хода, затяжной бой) → лобби: код `K7PQ`, список мест, кнопка **«Пригласить»** → `Telegram.WebApp.openTelegramLink('https://t.me/share/url?url=<link>&text=…')`, где `<link> = https://t.me/<bot>/<app>?startapp=<CODE>`. Запасной вариант — копировать ссылку.
5. Друг открывает ссылку → Mini App стартует со `start_param = CODE` → клиент сразу шлёт `room:join`. Если игра уже идёт — сообщение «Партия идёт, подождите следующую» и место наблюдателя за столом (видит стол, не играет) с автоматическим входом в следующую партию.
6. Создатель жмёт **«Старт»** (минимум 2 участника). Пустые места до выбранного числа игроков можно заполнить ботами переключателем «Добить ботами».
7. Дальше — стол, как в локальном режиме, но срезы приходят с сервера. Итоги партии и сессии — как сейчас; «Ещё партия» доступна создателю.
8. Вне Telegram (обычный браузер) страница тоже работает: вход анонимный, по нику, как раньше; ссылка `https://<host>/r/K7PQ` ведёт в то же лобби.

## 3. Архитектура

```
apps/server/            Node 22, TypeScript, tsx в dev, esbuild-бандл в проде
  src/
    index.ts            HTTP (Fastify): статика apps/web/dist, /healthz, вебхук бота
    ws.ts               WebSocket-шлюз (ws): сессии, маршрутизация сообщений
    rooms/RoomManager   комнаты в памяти: код, места, настройки, состояние лобби
    rooms/Room          одна комната: GameHost (вынесенный LocalHost), сессия дня, таймеры,
                        рассылка срезов viewFor(state, seat) каждому участнику
    auth/telegram.ts    проверка initData, извлечение пользователя
    auth/identity.ts    Identity: Telegram или анонимный токен
    bot/bot.ts          grammY: /start → кнопка «Играть»; setChatMenuButton при старте
packages/protocol/      zod-схемы сообщений клиент↔сервер (общие для web и server)
packages/host/          GameHost: логика LocalHost без DOM и без React (переезжает из apps/web/src/host)
apps/web/src/client/SocketGameClient.ts   реализация GameClient поверх WebSocket
```

Принципы: сервер — единственный судья; клиенту уходит только `viewFor`; события `apply` безопасны для рассылки всем (проверено ревью движка). Колода тасуется `crypto`. Таймеры — те же, что в `LocalHost`: ход, штраф 20 с, `tick` по `nextDeadline`, боты, удержание места 5 мин, удаление пустой комнаты через 30 мин.

## 4. Протокол (WebSocket, JSON)

Клиент → сервер: `hello {auth: {kind:'telegram', initData} | {kind:'anon', token, nick}}`, `room:create {settings}`, `room:join {code}`, `room:leave`, `room:settings {settings}`, `room:fillBots {on}`, `room:start`, `room:next`, `room:close`, `game:action {action, version}`.

Сервер → клиент: `hello:ok {me: {id, name, avatar}, room?: RoomState}`, `room:state {code, hostId, seats[], settings, status, fillBots, session}`, `game:view {view, version, events, deadlines, players}`, `session:results`, `error {code, message}`.

`ClientUpdate` для экранов собирается на клиенте из `room:state` и `game:view` — та же структура, что у `LocalGameClient`.

## 5. Идентификация и безопасность

- `initData` проверяется на сервере каждым подключением; токен бота хранится только в переменной окружения `BOT_TOKEN`.
- Анонимный вход: клиентский UUID-токен + ник; повторное подключение с тем же токеном возвращает место.
- Один игрок — одно место: второе подключение того же id заменяет первое (первое получает `error: replaced`).
- Действия проверяются движком; `version` отсекает устаревшие.

## 6. Деплой

- `Dockerfile` (multi-stage: сборка web + server, финальный образ `node:22-alpine`), `docker-compose.yml`: сервисы `app` и `caddy` (автоматический HTTPS по `DOMAIN`), `.env.example` (`BOT_TOKEN`, `BOT_USERNAME`, `APP_SHORT_NAME`, `DOMAIN`).
- Бот работает через **long polling** (не нужен вебхук и лишняя настройка); при старте выставляет кнопку меню на `https://DOMAIN/`.
- Команда деплоя: `docker compose up -d --build`. `/healthz` для проверки.

## 7. Тесты

- `packages/protocol`: схемы принимают/отклоняют сообщения.
- `packages/host`: тесты `LocalHost` переезжают вместе с кодом.
- `apps/server`: проверка `initData` (валидная/подделанная/просроченная); интеграция с настоящими WebSocket-клиентами: создать комнату, войти по коду, старт, полная партия двумя клиентами + ботами, переподключение с тем же токеном, замена подключения, таймер хода.
- `apps/web`: `SocketGameClient` против фейкового сокета; главная показывает Telegram-профиль; лобби и «Пригласить» (формирование ссылки).
- e2e: два контекста Playwright в одной комнате доигрывают партию.
